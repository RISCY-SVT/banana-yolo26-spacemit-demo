# Итоги Stage63

## Классификация

`stage63-rt206-plugin-fixed-int8-ep-regressions-persist`

Это исследование отдельного vendor runtime. Оно не меняет и не заменяет
принятый custom executor.

## Что изменилось в 2.0.6

Официальный архив `spacemit-ort.riscv64.2.0.6.tar.gz` имеет размер
15 002 263 байта и SHA-256
`bebcdfb7df6b49eefa3863afcd85a3da2aa83c3ae9252d7d856188c38a70b0e6`.
Публичные теги 2.0.5 и 2.0.6 указывают на один коммит, поэтому выводы сделаны
по бинарным пакетам.

Основная библиотека ONNX Runtime полностью совпадает с 2.0.5. Изменилась
`libspacemit_ep.so.2`: размер вырос с 5 703 872 до 5 962 176 байт, добавлены
недостающие экспортируемые методы plugin API. Пакет также получил полноценный
пример плагина.

## Результаты issue #1

- Q/DQ Conv без `kernel_shape`: по-прежнему работает точно; это контроль, а не
  новое исправление.
- Q/DQ Conv с `kernel_shape=[3,3]`: прежняя ошибка clip-minmax и последующий
  abort. Не исправлено.
- QLinearConv: прежний SIGILL, код выхода 132. Не исправлено.
- QLinearMatMul: прежний SIGILL, код выхода 132. Не исправлено.
- Официальный plugin sample теперь собирается, разрешает символы и загружается.
- Независимый uint8-плагин действительно назначается EP и выполняется точно.
- Полная INT8-модель YOLO26 по-прежнему завершается abort на этапе компиляции
  первого quantized Conv.

У официального Track2-примера обнаружена отдельная ошибка корректности:
31 892 из 32 768 значений отличаются от CPU-контроля. Исправление загрузки
плагина не означает корректность всех поставленных примеров.

## Полная модель

FP32 и FP16 успешно выполняются через SpacemiT EP. В преобразованных
подграфах находятся все 102 Conv и четыре MatMul; доля времени EP по профилю
составляет 99,34% для FP32 и 99,18% для FP16. Эти числа не являются точной
долей исходных ONNX-узлов, потому что граф преобразован.

INT8-сессия не создаётся, поэтому фактическое назначение и выполнение INT8
узлов на EP не доказано. Диагностический dump показывает только попытку
разбиения графа.

## COCO и производительность

Все четыре доступные поверхности прошли 5000/5000 изображений:

| Поверхность | mAP50-95 |
|---|---:|
| CPU FP32 | 0.404730651123 |
| CPU INT8 | 0.374594101159 |
| EP FP32 | 0.404745220420 |
| EP FP16 | 0.404686635006 |

CPU INT8 совпадает с принятым 2.0.5 по всем 5000 хешам выходов и детекций.
Выходы нового EP не побайтно идентичны 2.0.4, хотя итоговая точность COCO
практически та же.

Средние значения для 500 согласованных запусков:

| Поверхность | Среднее, мкс |
|---|---:|
| B120 CPU INT8 | 460031.116 |
| 2.0.6 CPU INT8 | 1022360.082 |
| 2.0.6 EP FP32 | 436560.705 |
| 2.0.6 EP FP16 | 357382.003 |

Все доступные маршруты 2.0.6 прошли по 1000 стабильных запусков. Длинный тест
INT8 EP не запускался, потому что сессия не создаётся.

## Вывод

В 2.0.6 исправлена упаковка и ABI плагинов, а независимый плагин реально
работает. Три ключевые INT8-регрессии и полный YOLO26 INT8 EP не исправлены.
Продвижение 2.0.6 как runtime по умолчанию не обосновано. Публикация
подготовленного комментария в issue #1 остаётся решением человека.
