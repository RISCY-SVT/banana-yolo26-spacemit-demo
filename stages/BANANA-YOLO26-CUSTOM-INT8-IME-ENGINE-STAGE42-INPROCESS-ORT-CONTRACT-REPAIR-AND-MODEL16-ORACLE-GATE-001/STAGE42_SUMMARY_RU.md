# Краткий отчет Stage42

Классификация: `stage42-host-oracle-policy-selected-model16-oracle-ready`.

Stage42 технически повторен по прямому разрешению пользователя. Первая попытка была только административной проверкой и не содержала работы с репозиторием, сборки или запуска на плате.

## Доказано

- Точная host-цепочка Stage41 воспроизведена на ORT 1.27.0.
- Для одного и того же входа `/model.4` host scalar, board scalar и board IME дают полностью одинаковый uint8-выход.
- Board IME совпадает с фиксированным host-оракулом: `mismatches=0`, `max_abs_diff=0`.
- Board ORT 1.20.2+spacemit не совпадает с host ORT. Первое расхождение локализовано в первом `QuantizeLinear`: 5 кодов из 1 638 400 отличаются на 1, при этом float-выход предыдущего Conv совпадает побайтно.
- Выбрана политика B: host ORT является источником корректности; board ORT используется только для интеграции, fallback, диагностики и времени.
- Измерительный цикл исправлен: ORT reference/model4 reference, сравнения и запись файлов исключены из hot loop.
- Подготовлены semantic и quantized оракулы для `model.16`; оптимизированный `model.16` не реализовывался.

## Следующий шаг

Рекомендуется Stage43 для соседнего острова `model.5 -> model.8`: сначала фиксированные host-оракулы и прямое изолированное профилирование на плате, затем не более одного точного custom-блока. Оракул `model.16` остается готовым для отдельной проверки повторного использования C2f-кода.

Не заявляются production readiness, default dispatch, полный custom engine, COCO/mAP, camera/full-image performance или оптимизированный `model.16`.
